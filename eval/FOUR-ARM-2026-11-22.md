## 1. 四臂定义（计划书 §12.1）

| 臂 | 配置 | 作用 | 执行环境 |
|---|---|---|---|
| L0 原生 | 无插件，standard preset | 基线 | **真机**（离线不可跑：需宿主 + 真模型） |
| L1 PTC | 仅 PTC preset，无本插件 | 对照：code-as-action | **真机** |
| L2 标准通道 | 本插件 + standard preset，通道=标准 | 无代码通道路径 | 真机（主）+ 离线结构（辅助） |
| L3 代码通道 | 本插件 + PTC preset，通道=代码 | 核心实验臂：同 preset，仅变治理 | 真机（主）+ 离线结构（辅助） |

任务集：10 个既有任务 + 4 个长任务（15/30 回合量级）+ 2 个大文件任务（>2,000 行）。判据：

- **H1**：L3 与 L1 在 `|ΔN| ≤ 1` 的成对样本上，总 token 低 ≥15%，且 10 个任务中 ≥7 个成立。
- **H2**：L2 的上下文增长斜率 ≤ L1 的 1/3；交叉点 ≤6 回合。
- 成对比较纪律（§5.8）：`|ΔN| > 1` 的样本视为不可比，单独列出。

## 2. 指标定义（§12.2）

| 指标 | 定义 | 用途 |
|---|---|---|
| `N` | 请求数 | 一等指标 |
| `tokens_total_strict` | `input + output`，不含 `cacheRead` | 严格口径（结论用） |
| `tokens_total_with_cache` | 含 `cacheRead` | 参考口径，不得单独用于结论 |
| `C_max` | 单请求最大上下文 | 增长阶证据 |
| `cache_hit_ratio` | `cacheRead / input` | 换基成本证据 |
| `rebase_count` | 换基次数（计划性 / 非计划性分列） | 前缀策略证据 |
| `verify_pass_rate` | 验收项通过率 | 质量约束 |
| `channel_source` | `preset` / `bridge` / `none` / `standard` | 归因前提 |

硬规则：任何对外结论必须同时给出两个口径（0.4.x 的 28.9% vs 134.9% 教训）。离线跑批没有真 cacheRead 语义，`tokens_total_with_cache` 仅供管线核对。

## 3. 离线结构跑批（本机可执行，2026-11-22）

执行：`node eval/tools/run-four-arm.mjs`（mock 流驱动**真实驱动器代码路径**——同一份 `SingleStreamDriver`，验证四臂装配与度量管线）。产物：`eval/runs/four-arm-offline.json`（schema `four-arm-offline/1`）。

| 臂/任务 | N | strict | C_max | outcome | channel_source |
|---|---|---|---|---|---|
| L2/T1-single-read | 2 | 1280 | 960 | completed | standard |
| L3/T1-single-read | 2 | 880 | **159** | completed | bridge |
| L2/T2-write-verify | 2 | 1120 | 935 | completed | standard |
| L3/T2-write-verify | 2 | 745 | **153** | completed | bridge |
| L2/T3-multi-step | 4 | 1640 | 1092 | completed | standard |
| L3/T3-multi-step | 2 | 635 | **158** | completed | bridge |

离线结构结论（仅管线级，非成本结论）：

1. **装配可用**：四臂的 channel/tier/codeSource 判定、度量字段（N / strict / with_cache / C_max / rebase_count / channel_source）在真实驱动器上全部产出。
2. **通道差异可见**：L3 的 C_max 显著低于 L2（代码通道协议段 0 字符 / 200 字符 vs 完整协议段 ≈3.1k 字符）——方向与 §5.7 成本模型一致；`|ΔN| ≤ 2`，成对样本结构可比。
3. **不可比样本纪律**：T3 的 `ΔN = −2`（L3 用一个 run_code 程序替代三次逐轮读取）——按 §5.8 应标"不可比"（N 差异是设计差异：逐轮 vs 单程序），真机报表中单独列出。
