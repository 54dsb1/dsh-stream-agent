## 2. 计划语义的落地决策（与 v0.4.0.md 的差异点，逐条给理由）

1. **F5 默认开启而非 opt-in**：计划的准入条件是"净增 ≤0"。差分注入设计（新计划全量
   一次、此后只注变化；无变化不产生任何块）使静态注入增量收敛于"计划清单一次 +
   每次验收一行"，而它换来的是过早 final 拦截（减少整轮重试）——净增判定以 R3 重跑
   的逐任务对照为准；若重跑显示净增 >0，`enablePlan: false` 是配置级回退点，无需改码。
2. **F6 的"有意图无回执"判定保留 failed 态**：计划原文是"有意图无回执"停机核对；
   实现把"已发生但失败"（receipt ok=false）与"不确定"（无 receipt）分开——只有
   "不确定"触发停机核对，失败意图只在 CLI 列出供参考（失败不算未发生，也不该阻断）。
3. **F7 的触发粒度是"回合边界 + 追加区字符数"**：计划未指定触发量；选字符数（160k ≈
   40k tokens）而非请求数，因为缓存的代价单位是 token。可配可关。
4. **F7 的"原文可按 request:N 回取"落地为 obs 句柄**：宿主没有 request:N 寻址面；
   `obs:read:seg-t<turn>-<i>@v1` + `tf-peek`/`peekHandle()` 等价实现该语义。
