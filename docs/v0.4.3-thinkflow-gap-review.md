## 3. 仍存的不足（按 v3 §7 阶段表排序，每条给收口版本）

### 0.4.4 要收的（P0-9 + P0-10 T0）

1. **执行器差距（清单 §0.6 表）**：`tf-code` 现状 = `function-body` 单形态 + 固定 `tools` 绑定 + cwd 透传；缺 `stateOwner` 跨调用状态、三态 `programFormat`、完整 `SandboxExecutionPolicy`、多命名空间 + `errorClass` 类型化拒绝、描述符全量呈现、`release` 生命周期。收口方式 = 迁 `deepseek-harness` `packages/ptc-runtime`（MIT，钉 commit + conformance 套件），协议快照 `v3` 只加 `state`/`format` 两属性 + `tf-state` 一条命令。
2. **无损成本层（T0）**：精确去重、写回执折叠、空 prose 不注入、`tf-call` 映射表惰性披露——全部未做。

### 0.5.0 要收的（P0-1~4 + T1）——**结构性收益最大的两步在这里**

3. **收尾契约**："流末无 `tf-final` → 必发 nudge"（`loop.ts` missing-final-nudge）仍是 N 最大加法源（清单 §1.3：W1 用满 9 请求的主嫌疑）；无框架验收、无 awaiting 终态、无同轮交付。thinkflow 实测同轮交付 10→6 请求、`check_completion` 满足即结束。
4. **回灌契约**：`info_gain` 三档 + 自写读回执 + native 骨架化——与 thinkflow `max_content_chars=0` 方向相反（清单 §0.1：0.1.0 少回灌掉完成率 6/10 的自身判例）。R2 +60%、C1 +33% 的请求差是它付的。
5. **fence gate**（现存风险）：正文代码围栏内的 `tf-*` 会被真执行（thinkflow `verified-edits-20261118.md` 记录过同类事故）；reasoning 通道的 `tf-*` 会被静默丢弃。
6. **确定性定序**：并发完成顺序仍会进 prompt（`#buildInjections` 按 `#commands` 插入序）；混合通道（native + `tf-*`）仍无全序。
7. **T1 外部化**：文件内容仍整块进上下文（≤8,000 字符全量）；依赖 P0-9 的 `stateOwner` 才能落地，这是 v3 把 P0-9 排在 0.4.4 的原因。

### 0.5.1 要收的（P0-5 + P0-8 + T2/T3 + P1-2/P1-3）

8. **段边界投影**：整块丢 append 头不留任何说明，模型不知道丢了什么（清单 §2.8 的"突然少一段"）。
9. **对账三态**：`committed/unknown/aborted` 终态、`receiptHash` 绑定、`tf-final` 前强制 reconcile——0.4.3 只做了最小对账。
10. **recall 语义**：`tf-peek` 无 `offset`/`query` 模式，无 `request:N` 原始要求引用。

### 0.6.0 要收的（P0-7②③ + P1-1 + P1-5）

11. **reset 预算**：reset 无 `minRequestsBetweenResets` 约束、无 `window-limit` 强制例外；lifetime 未上升为类型约束（transient 块仍可能进 history——目前靠 `DURABLE_TAIL_PREFIXES` 约定）。
12. **协议面互斥矩阵**：native 与 `tf-*` 同轮混用仍被协议明文允许（清单 §2.2 的旧读风险）；无协议面指纹。
13. **PTC 对照臂**：无第三臂数据前，"⊇ PTC"只是文档措辞（v3 P1-5：比 `costPerPass / N / 可继续率 / 验收覆盖率`）。

### 明确不追（不做清单 v3 第 1–4、6–9、11 条）

中途打断、FIFO 单 worker、thinking 主路径、Python 运行时、自建平行执行器语义、模型摘要压缩、自动回滚/重放、为命中率限主动权、100% 命中率、砍输出换降幅。这些不是差距，是定位。

## 4. N 与成本的账：0.4.3 之后站在哪

- **0.4.3 不动行为**，N 与 token 用量与 0.4.2-beta.1 同水位（2026-11-15-v02 批次：N 59、四分量 28.9%（446,410 → 129,178；本批缓存写两臂为 0）、严格二分量 134.9%（52,682 → 71,066，插件更高）、checks 9/10；22.3% 系 cacheRead 二次计入的错值已作废）。0.4.3/0.4.3.1 的收益是两样：**失败可控**（前缀破坏从"任务炸掉"变为"记账 + 有界放行 + 兜底交付"，且混合尾误判已修）与**全部可复算**（七列尺子 + 五类探针）。
- **上游对照的最新刻度**：thinkflow 2026-11-19 在维护类任务上 23 请求 / 199,166 tok（对 Pi 省 49.3–70.1%）。折算每任务 ≈2.3 次请求。清单 v3 的目标是 N 20–26（每任务 2–2.6 次）——同水位，但路径不同：thinkflow 靠 flow 立即打断（我们结构性不做），我们靠 **P0-2 框架验收免掉验证请求 + P0-1 可预测性门控 + T1 外部化**（0.5.0/0.5.1）。
- **总成本目标 8–11%**（v3 §0.5 重算）：下界 37,654 = 8.4%，由"输出不能砍"决定（现输出 28,284 已超 95% 门槛 22,320）。这个目标的达成版本是 0.5.1/0.6.0，不是 0.4.3。

## 5. 复核结论

1. **收口**：2.7（消息所有权）、2.11（成本口径）两处差距在 0.4.3/0.4.3.1 结构性消除——wire 边界从"两处局部断言"升级为"承诺前缀断言 + 三类成因 + 有界放行 + 兜底交付"，成本从"三套比值混流"升级为"七列可复算（costPerPass 待价格快照）+ 四列同表 + diagnostic-only"。
2. **推进**：2.9（恢复）补了最小对账与 ack 语义；2.8 的 reset 计数尺子就位；2.3 的反馈字节分类就位——0.5.x 的行为变更全部有了同口径的对照组。
3. **最大的剩余差距**集中在 0.5.0 的两项：收尾契约（nudge 强制）与回灌契约（骨架化方向）——它们同时是清单 §1.3 的 N 加法源 #1/#3，也是与 thinkflow 差距的主因。执行器差距（P0-9）排 0.4.4，因为 T1 外部化依赖它。
4. **复核依据可全部重放**：`npm test`（385/385，1 例预置跳过）中的 `test/v043-prefix.test.ts`（K1–K5 内核断言、P1–P4 四类探针、M1–M6 尺子）与 `test/loop.test.ts` B1（P0-6⑤ 新契约）；离线门禁 3/3（G4/G5/G6 真机项按纪律待批次，未过前不发布 npm）。
