## 2. 设计决策（与"易变尾"原始语义的差异，逐条给理由）

1. **转正只限"事实类"**：观测/peek/工具结果/回灌/计划/回执是发生过的事实，转正后历史
   只增不改（与 O3 句柄目录、assistant 正文摘要同权）。nudge/degraded/error 保持瞬态：
   它们是**指令**，转正会让下一回合把"预算告急/final 被拒"当现状（计划被拒的例外由
   "拒绝注入附带计划快照"覆盖——快照随每次拒绝重新生成，不过期）。
2. **计划走差分链而非全量重放**：转正后历史持有"全量 v1 + 增量 diff"，模型按时间线
   重建当前状态——与句柄目录增量同一模式，不做全量重放（破坏前缀单调）。
3. **缓存口径以宿主 dsh-llm Usage 为权威**：`inputTokens` 只是未命中输入，计费输入 =
   input + cacheRead + cacheWrite。适配器不上报时字段缺省（不写 0 噪声），预算与旧行为
   逐字节一致。
4. **上限放宽不是成本**：maxReentries 只在真打转时触顶；打转的根因（V-a/V-b）已修，
   触顶频率应当下降——放宽只为"计划+实现+验收"这类合法长任务不被误杀。

## 3. 验收口径

- `npm test` 全绿（364 用例：360 + v042-cache 4 例）；
- 真机复跑（待批次）：同一任务族重跑，对照指标 = 缓存命中率（期望从 ~64% 升至 ≥90%，
  由回合台账 `cacheHitRatio` 直接取证）+ 重入上限触顶次数（期望 0）；
- 前缀单调护栏（O6 preflight fail-closed）零违例——转正只走追加区，护栏语义不变。

- 0.4.1-beta.2 交付了记忆蒸发的主修（转正机制 + parser 三修 + 续写）与宿主一致性补丁；
