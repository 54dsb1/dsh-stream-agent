# dsh-stream-agent

[![ci](https://github.com/54dsb1/dsh-stream-agent/actions/workflows/ci.yml/badge.svg)](https://github.com/54dsb1/dsh-stream-agent/actions/workflows/ci.yml)
[![license](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](./LICENSE)

[简体中文](./README.md) | English

**A single-stream heart for DeepSeek Harness.** Instead of the turn-based loop, the model
writes every `tf-*` command inside one streamed response; commands execute the moment they
close; results are handle-ized and fetched on demand; the context only ever appends — never
rewrites. The goal: drive per-task tokens down to a fraction of the native loop while turning
every failure, cancellation, and sandbox denial into an **auditable fact** instead of an
error string.

Measured on real connections (10 tasks, two arms, same `deepseek-flash` model, stamp
`2026-11-15-v02`, four-component totals recomputed by `summarize.cjs`): **28.9% of the
native loop's tokens with parity on correctness**. The historical 22.3% figure comes from an
earlier batch — the two are not comparable; see the honest note in
[eval/RESULTS.md](eval/RESULTS.md) §6. The R3 rerun will re-measure both arms in one batch.

## 1. What problem does it solve

The native loop is turn-based: one request per step, tool results stuffed back into context
in full, the model reads everything before deciding what's next. Three things happen at
once — **too many requests, observations re-injected repeatedly, and the prefix cache broken
over and over**.

This plugin takes over that layer and changes exactly three things:

1. **Single stream** — the model writes all its `tf-*` commands consecutively inside one
   stream; the parser parses chunk by chunk and dispatches each command the moment it
   closes, executing independent commands in parallel without waiting for the stream to end.
2. **No observation backflow** — tool output returns a handle by default; the model sends
   `tf-peek` to fetch details by line range. Injection volume flips from "we guess" to "the
   model decides".
3. **Monotonic prefix** — context assembly only ever appends to the tail; a byte-level
   assertion runs before every request and refuses to send on any unrecorded drift
   (fail-closed). Better a clean failure than a burnt cache.

No model retraining, no upstream source changes — everything exists as plugin entries +
patches.

## 2. Install: the dedicated profile (the only supported shape)

```bash
# 1) Copy the dedicated profile template (local dev uses link:; npm installs pin exact
#    versions — no ^/~ ranges)
cp -r profiles/stream ~/.dsh/profiles/stream

# 2) Install precheck (S2): read-only; the target must be stream / stream-headless
node scripts/install-check.mjs --profile ~/.dsh/profiles/stream --dry-run

# 3) Startup self-proof: the banner should read TAKEOVER-ACTIVE … code=off … profile=stream
dsh --profile stream

# 4) Install/uninstall regression (optional, 10 rounds of add → self-proof → remove → restore)
node scripts/install-cycle.mjs --dsh dsh --profile stream --rounds 10

# Uninstall: the bundle layer disappears as a whole; the host loop is restored atomically.
# Full removal = delete the profile directory.
dsh plugin remove @hugesb/dsh-stream-agent --profile stream
```

- Headless entry: use `profiles/stream-headless` (no preset bundle — headless hosts have no
  preset registry; the tool surface is decided by the profile).
- The composition order `dsh-base → main bundle → preset bundle → entry` is a contract;
  reordering counts as an assembly change and needs re-acceptance. Details in
  [profiles/stream/README.md](profiles/stream/README.md).
- The `agent-loop` disable lives **only in the main bundle's cordis.patch.yml** — `plugin
  remove` unwinds it atomically (C4). The profile patch layer only overrides the preset
  registry default and never takes over the loop.
- Installing into `web` / `desktop` is rejected by `install-check`; bypassing the check
  still fails fast with `E_DOUBLE_LOOP` (profile id + remediation hint) — never a silent
  coexistence (C2/S3).
- `dsh plugin` needs `pnpm` on PATH (or a configured `pnpmCommand`).
- **Old session logs (0.2.x and anything written before 0.3.0 shipped)**: 0.3.0 fixes how the
  v4 tool lifecycle is written — logs written earlier make the desktop app show
  "failed to load history" (`tool/call … has no advertised tool lifecycle`; the host marks the
  whole log corrupt — no data was lost). After upgrading, run
  `node scripts/repair-session-logs.mjs --write` once (drop `--write` to preview the list;
  it backs up to `.bak-<timestamp>` and clears the projection cache), then history loads.

For development you can still stack temporarily without installing:
`dsh --profile headless --patch ./patches/takeover.yml headless "task"`.

## 3. Run modes (four control-bar modes)

The interactive panel (`dsh-stream-agent bar`), the CLI (`dsh-stream-agent mode lean`) and
the desktop page all read the same `kernel/modes.ts`. Modes only provide defaults;
**explicit config always wins over mode values**.

How much does each save? Honest answer: only "default vs native loop" has a measured figure
(~29%, 10 tasks, two arms); the other tiers are directional and labelled "not separately
benchmarked" — we do not present unmeasured numbers as percentages.

| Mode | Token saving | Availability | Notes |
| --- | --- | --- | --- |
| `balanced` (default) | Baseline (~29% of the native loop) | Default, works out of the box | tf-code off by default (K1) |
| `lean` | Higher | Ready | 60k budget ladder + parallelism 2 + no tf-code; the gap widens on long sessions |
| `compat` | Lowest | Ready | Full read-back restored, parallelism 1; still below the native loop — the single-stream protocol itself is the saving |
| `power` | Highest (best on data-processing) | Needs host PTC runtime | The only mode that turns tf-code on; on plain read/write tasks it costs slightly more |

Mode → config mapping (explicit config > mode > built-in defaults):

| Mode | `selfReadFeedback` | `enableCode` | `persistFallback` | Parallel | Reentries | `budgetTokens` |
| --- | --- | --- | --- | --- | --- | --- |
| `balanced` | `receipt` | `false` | `true` | 3 | 8 | — |
| `lean` | `receipt` | `false` | `true` | 2 | 6 | 60,000 |
| `compat` | `full` | `false` | `true` | 1 | 12 | — |
| `power` | `receipt` | `true` | `true` | 3 | 10 | — |

One-line decision guide: **stay on `balanced`; switch to `lean` when the bill matters;
`compat` when diffing against the native loop; `power` for programmatic data work.**

## 4. The tf-* protocol (11 commands)

The parser (`src/kernel/parser.ts`) is the authority; full semantics in
[docs/protocol.md](docs/protocol.md).

| Command | Purpose | Where results go |
| --- | --- | --- |
| `tf-write` | Write a file (body = raw content) | Success = ledger only; failure injects `[tf-stream:error]` |
| `tf-read` | Read a file (optional offset/limit line ranges) | First/changed results injected in full (≤8000 chars, head+tail kept); reading a path you wrote this task returns a receipt only (lines+sha256, O7) |
| `tf-edit` | Exact replace (body uses `<<<<<<< OLD` / `=======` / `>>>>>>> NEW` markers; maps to host edit) | Success = ledger; match failure is a structured error — **no fuzzy matching, never silently rewrites the whole file** |
| `tf-append` | Append-only (optional anchor; maps to host edit / apply_patch EOF anchor) | Success = ledger; position and newline rules are deterministic |
| `tf-grep` | Content search (maps to host fs-search), returns matching lines with numbers | First/changed injected in full; over-limit → handle |
| `tf-glob` | Filename search, returns paths only | Same |
| `tf-bash` | Run a command (pwsh on Windows) | Success = ledger; use `tf-peek` to see output |
| `tf-peek` | Fetch a line range from a handle | Injected on demand |
| `tf-plan` | Declare/revise the plan and acceptance items (`- [id] description` lines) | State lives driver-side; requests carry **diffs only** |
| `tf-final` | Finish (summary must contain the answer verbatim) | Flagged premature while acceptance items are unverified (F5) |
| `tf-code` | Programmatic tool calls (**off by default**; `power` mode or explicit opt-in) | Values within the cap injected in full; over-limit → skeleton+handle; failures carry `kind` + retry verdict |

Common attributes: `id` (auto-numbered when omitted), `depends_on` (cycles detected and
named), `accepts` (acceptance links, F5). Two token-saving disciplines are written into the
protocol text: **don't re-read files you just wrote** (you get a receipt) and **don't use
tf-bash as a search tool** (tf-grep/tf-glob are cheaper and return matching lines only).

## 5. Plan, recovery, long sessions (on by default, each with an off switch)

**Plan & acceptance (F5)** — completion semantics for composite tasks; "claims done without
a receipt" is structurally intercepted:

```
<tf-plan id="p1">
- [a1] generate intro.md
- [a2] generate summary.md
</tf-plan>
<tf-write path="intro.md" id="w1" accepts="a1">…</tf-write>
```

- Acceptance items can only be verified by **successful command receipts** (`accepts="..."`);
  the model saying "done" is not evidence;
- `tf-final` converges only after every acceptance item has a receipt; otherwise a premature
  hint guides the model to finish or revise the plan;
- Plan state lives driver-side; requests carry **diffs only** (full plan once, then only
  added/verified/removed lines);
- Turn off: `enablePlan: false`.

**Recovery intent (F6)** — honest state after a hard kill, zero injection:

- Before dispatching a mutating command (tf-write/tf-edit/tf-append) the intent
  (op/path/content fingerprint) is fsync'd to `~/.dsh-stream-agent/intents/<session>.jsonl`;
  the receipt is appended the moment the command settles;
- Three-state semantics under kill -9: killed before the write = didn't happen; killed
  mid-write = uncertain; killed after the write but before the receipt = file is complete on
  disk yet the ledger shows "intent without receipt" — **no automatic replay**;
- On resume, "intent without receipt" blocks the turn immediately (no request, zero
  injection); triage with `dsh-stream-agent intents`, close with `--ack <session>` after a
  human check;
- Kill drill (runs offline): `node eval/tools/f6-kill-drill.cjs --rounds 10` — 10 SIGKILL
  rounds across three kill points; 0 replays, 0 duplicate writes, all three states
  distinguishable;
- Turn off: `enableIntents: false`; warn-only: `resumeIntentPolicy: 'ignore'`.

**Long-session segment boundary (F7)** — bounded context growth
([ADR-001](docs/adr-001-segment-boundary.md)):

- When the append region exceeds `segmentMaxChars` (default 160k chars ≈ 40k tokens), whole
  blocks of the old segment are dropped at the next turn boundary — **never summarized,
  never rewritten** (ADR chose whole-block discard and rejected host compaction);
- Discarded originals are handle-ized (`obs:read:seg-*`) and retrievable via `tf-peek` /
  `peekHandle()`;
- The cost is stated honestly: the first request after a drop is a cold cache request; every
  drop is recorded in policyLog and the ledger — never silent; drops only land on turn
  boundaries (tool calls and their results never split);
- Measured: 50 turns × 2 requests = 100 requests with 0 prefix violations and
  last/first ≤1.5×;
- Turn off: `segmentMaxChars: 0`.

## 6. tf-code: the opt-in channel (K1–K6)

- **Enable**: `power` mode, or `enableCode: true` in config (requires the host to mount
  `@deepseek-ai/dsh-ptc-runtime`). The default assembly declares 0 characters of tf-code —
  the model cannot hallucinate it; no session-level dynamic toggles (the protocol section is
  frozen at construction).
- **Execution boundary (stated honestly, no isolation promises)**: the sandbox covers **file
  effects only** — programs can reach the network and see processes; the Windows ACL tier
  reports `enforcement=partial`; `danger-full-access` has no constraint at all. These facts
  are recorded per run (`mode` / `denied` / `enforcement`) and `partial` is always visible.
- **Failure semantics (K3)**: the eight runtime `kind`s are preserved verbatim (exception /
  timeout / abort / worker-exit / invalid-output / output-limit / protocol /
  sandbox-unavailable) plus the plugin-level `quota-exceeded`; each kind carries a
  retryable/not-retryable verdict; sandbox denials are not code errors — the hint never says
  "fix your code" for permission problems.
- **Quota (K5)**: ≤64 subcalls, ≤256 KiB output, ≤300 s wall clock (`codeQuota` configurable);
  breaches terminate structurally, not with a hint.
- **Cancellation (K4)**: the turn signal reaches resolve and bound calls; after abort the
  driver waits for in-flight cleanup before settling; abort and timeout are accounted
  separately.
- **Result visibility (F3)**: the first successful/changed value is injected in full when
  within the 4000-char cap — saving a tf-peek round trip; over the cap it becomes skeleton +
  handle. The full-echo channel is never restored.
- Real-machine five scenarios (success / failure / cancel / denial / partial):
  [eval/tools/manual-code-scenarios.md](eval/tools/manual-code-scenarios.md).

## 7. Metrics & evaluation (where the numbers come from)

Every tool runs offline with zero API calls; real-machine batches are executed manually
(propositions in [docs/TEST-PROPOSITIONS.md](docs/TEST-PROPOSITIONS.md), ≈¥2 per task).

| Tool | Purpose | Current evidence |
| --- | --- | --- |
| `eval/tools/summarize.cjs` | M1 four-component totals (input/cache-read/cache-write/output; missing components marked "unavailable") | Stamp 2026-11-15-v02: baseline 446,410 → plugin 129,178 (28.9%), per-task rows in summary.json |
| `eval/tools/replay-check.cjs` | M3 replay consistency (replayed tree hash == live tree hash) | Plugin arm **10/10** after fixing two extractor root causes; the native-loop arm's limitation is recorded honestly |
| `eval/tools/t3-cells.cjs` | M2 T3 three-cell baseline (B / A-1a / A-1b first-request split) | Script + three patch arms ready; the tf-code section measures 1,175 chars; cell numbers await a same-batch real run |
| `eval/tools/runner.cjs` | R3 eval matrix (two arms × 10 tasks + sentinels) | 0.3.0 rerun pending (new protocol surface) |
| `eval/tools/f6-kill-drill.cjs` | F6 kill drill (SIGKILL × 10 rounds × three points) | Passed offline: 0 replays, 0 duplicate writes, three-state verdicts |
| `npm run check` | R2 assembly/doc consistency (4 checks) | Re-runnable with one command |
| `npm run gate` | R4 release gate (6 items) | Offline items judged in place; real-machine items (G5/G6) marked honestly — no release until green |

Discipline: per-task tokens = Σ(input + cacheRead + cacheWrite + output) (four components,
per-request usage kept verbatim); missing cache components are marked "unavailable", never
zero-filled; title side-requests are excluded from both arms; the two-component figure is
reference-only and always labelled.

## 8. Control bar & desktop page

- **Load banner**: stderr onboarding panel (takeover state / current mode / first four steps
  / intent hint); `announce: true` prints one mounted line per entry — the plugin proves it
  is loaded.
- **CLI** (`dsh-stream-agent`):
  - `bar` interactive panel: 1-4 to switch modes, ↑↓ to move, `l` for zh/en, `?` full guide,
    `r` reset, `q` quit;
  - `status` / `mode <balanced|lean|compat|power>` / `lang <zh|en>` / `--json`;
  - `intents` lists per-session "intent without receipt" (F6 triage); `intents --ack
    <session>` closes them after a human check;
  - `help` prints the full mode guide.
- **Desktop page**: the client sidebar panel shows takeover state, current mode and source,
  six effective parameters, four mode cards (when to choose / trade-offs + saving tier +
  availability), zh/en switch; writes go through the `streamAgentRuntime` service back to
  the loop (in-memory + `control.json` single source of truth) with a multi-window 409
  fence; config/env-locked controls render disabled; read-only fallback when the loop is
  not taken over.
- **State file**: `<stateDir>/control.json`; precedence `config > env > control.json >
  defaults`; a corrupt file warns and falls back — it never blocks loading.

## 12. Known limitations (summary)

The full list lives in [docs/limitations.md](docs/limitations.md). Highlights:

1. **Write-batch tasks** that exhaust the reentry budget exit with code 1 while the artifacts
   are correct — the guard means "budget exhausted", not "task failed".
2. **The tf-code sandbox covers file effects only**: programs can reach the network;
   Windows reports `partial`; `danger-full-access` is unconstrained — verify before use.
3. **Segment-boundary cache reset**: the first request after a drop is a cold cache request
   (inherent cost of the whole-block-discard route).
4. **The native-loop arm's replay evidence is limited**: write calls in v4 session logs are
   not parseable (marked "not replayable"; checks remain the correctness oracle).
5. **Queued tasks + segment boundary**: consecutive `pushUserTask` calls anchor the boundary
   at the last task block; merge related goals into one task text when they need shared
   context.
